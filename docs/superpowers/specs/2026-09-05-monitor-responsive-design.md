# 系统监控页平板至 PC 自适应设计

## 目标

在不减少监控数据、不改变接口调用和现有视觉语言的前提下，使系统监控页在 `768px` 至桌面宽度范围内保持清晰、无横向溢出且便于操作。

## 范围

- 调整系统监控页的页头、KPI 卡片、资源仪表卡片、趋势图和实时活动布局。
- 调整系统监控页所依赖的共享侧栏在平板宽度下的占位方式。
- 不修改其他业务页面的正文布局。
- 不处理低于 `768px` 的手机布局。
- 不改变接口、字段、轮询周期、主题颜色和信息密度功能。

## 采用方案

采用响应式网格重排。各宽度继续展示全部数据，不使用整页横向滚动，也不隐藏监控指标。

未采用的方案：

- 固定桌面画布并横向滚动：阅读和触控体验较差。
- 平板端隐藏次要指标：会减少管理信息，不符合监控页用途。

## 断点与布局

### PC：`≥1200px`

- KPI 区保持 5 列。
- CPU、内存、磁盘、系统信息保持 4 列。
- 趋势图与实时活动保持 `1.6fr / 1fr` 双栏。
- 页面继续使用现有紧凑间距和完整侧栏偏好。

### 平板横屏：`1024–1199px`

- 侧栏默认显示为 `60px` 图标栏，不覆盖或改写用户的桌面侧栏偏好。
- 点击侧栏按钮后，以浮层形式展开完整侧栏，不挤压正文。
- KPI 区使用 3 列，第二行自然承载剩余 2 项。
- 资源仪表区使用 2 列，形成 `2×2`。
- 趋势图与实时活动保留双栏，但允许实时活动栏适当缩窄。

### 平板竖屏：`768–1023px`

- 侧栏行为与平板横屏一致。
- KPI 区使用 2 列；最后一项保持普通卡片宽度，不跨满整行。
- 资源仪表区使用 2 列。
- 趋势图与实时活动改为上下排列。
- 页头操作区允许换行，标题始终保持左对齐，刷新按钮维持可点击尺寸。

## 组件调整

### 监控页容器

- 为页面添加稳定的语义类名，响应式规则集中在 Modern UI 的全局样式中。
- 所有网格子项设置 `min-width: 0`，阻止长文本撑宽页面。
- 页面根节点宽度不超过可用内容区，禁止产生文档级横向滚动。

### KPI 卡片

- 仅改变列数，不改变卡片内容和颜色。
- 保持数值为视觉焦点，标签可在必要时换行，但不得被裁切。

### 资源仪表卡片

- 仪表尺寸从固定 `180px` 改为按容器宽度计算，并设置合理上下限。
- CPU 型号、操作系统名称和运行时间允许断行。
- 键值行的值区域设置最大宽度和换行规则，避免撑开卡片。

### 底部图表

- 平板竖屏下趋势图与实时活动上下排列。
- 图表继续使用现有数据和高度，不压缩坐标标签。
- 实时活动中的时间、级别和消息保持原顺序，长消息在自身区域换行。

### 侧栏

- 桌面端继续使用现有展开/折叠偏好。
- 平板首次进入或从桌面缩窄时显示图标栏。
- 展开完整侧栏时显示遮罩，点击遮罩、选择菜单或按 `Escape` 后收回。
- 平板浮层状态不写入桌面侧栏偏好。

## 数据与错误处理

- 保持 `/boot/dashboard-stats`、`/boot/stats` 和 `/system/openLogs/json` 请求不变。
- 保持 10 秒轮询不变。
- 加载失败提示继续位于页头下方，并允许在窄宽度换行。
- 响应式状态只由视口宽度和临时侧栏浮层状态决定，不进入业务数据流。

## 验收标准

- 在 `768×1024`、`1024×768`、`1180×820`、`1366×768`、`1440×900` 和 `1920×1080` 下检查系统监控页。
- 所有测试尺寸下 `document.documentElement.scrollWidth <= window.innerWidth`。
- KPI、四张资源卡和底部两块内容均完整可见，不重叠、不被截断。
- `768–1199px` 下侧栏默认只占 `60px`，完整展开时覆盖正文而不改变正文宽度。
- `≥1200px` 下现有桌面侧栏偏好和页面结构保持不变。
- 浅色、深色主题各至少在一个平板尺寸和一个桌面尺寸下完成视觉检查。
- 现有监控数据加载、刷新按钮和自动轮询行为不变。

## 测试方式

- 使用内置浏览器视口覆盖逐一检查验收尺寸。
- 使用只读脚本检查视口宽度、文档滚动宽度和主要网格实际列数。
- 运行 Modern UI 现有构建或语法检查。
- 检查浏览器控制台，确保没有新增错误和警告。
